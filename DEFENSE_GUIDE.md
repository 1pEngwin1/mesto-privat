# Пояснение проекта для защиты

## Краткий рассказ

«Я подключил Mesto к API Практикума. При запуске параллельно получаю профиль и список карточек, затем отображаю данные сервера. Профиль, аватар и карточки изменяются отдельными запросами. Лайк синхронизируется с API и счётчик обновляется из ответа. Удалять карточку может только её владелец, а перед запросом открывается подтверждение. Для варианта 3 по клику на логотип открывается статистика карточек. Сборка настроена для GitHub Pages, а Actions публикует только папку `dist` в отдельный публичный репозиторий».

## Структура кода

- `src/scripts/api.js` отвечает за HTTP-запросы, заголовки и обработку ошибок.
- `src/scripts/card.js` создаёт DOM карточки и синхронизирует сердечко со счётчиком.
- `src/scripts/main.js` связывает формы, модальные окна, карточки и API.
- `src/styles.css` содержит стили макета и мобильной версии.
- `index.html` содержит шаблон карточки, шаблоны строк статистики и все модальные окна.

## Как объяснить API

Для всех запросов используется один `request()`. Он добавляет заголовки `authorization` и `Content-Type`, отправляет запрос и проверяет `response.ok`. Если сервер вернул ошибку, обработчик читает тело ответа и выбрасывает `Error`; форма показывает сообщение в toast-уведомлении.

При старте `Promise.all([api.getCards(), api.getUserInfo()])` экономит время ожидания: оба запроса выполняются параллельно. Если один не проходит, пользователю показывается сообщение, а интерфейс остаётся доступен в режиме предпросмотра.

## Как объяснить лайк

Перед запросом код определяет, есть ли ID текущего пользователя в `card.likes`. Если лайк уже стоит, отправляется `DELETE`; если нет — `PUT`. Сервер возвращает обновлённую карточку, поэтому интерфейс меняется по фактическому ответу, а не по предположению клиента. `card.js` получает новую карточку и обновляет `aria-pressed`, класс сердечка и число лайков.

## Как объяснить удаление

Кнопка корзины появляется только если `card.owner._id === currentUser._id`. Нажатие открывает модальное подтверждение. После подтверждения отправляется `DELETE /cards/:id`, и карточка удаляется из DOM только после успешного ответа.

## Как объяснить вариант 3

Логотип получает актуальный массив карточек с сервера. Для числа пользователей считаются уникальные владельцы карточек. Общее число лайков — сумма длины массивов `likes`. Для чемпионата лайков каждому пользователю собирается множество ID разных карточек, которые он лайкнул; размер наибольшего множества и есть максимальное число лайков от одного пользователя, а имя этого пользователя — чемпион. Три карточки с самым длинным массивом `likes` выводятся в списке популярных.

## Как объяснить деплой

`base: './'` заставляет Vite использовать относительные пути, которые подходят для сайта в подпапке GitHub Pages. Workflow стартует при push в `main`, устанавливает Node.js и зависимости, запускает `npm run build`, затем отправляет только `dist` во внешний публичный репозиторий. Исходный код остаётся в приватном репозитории.

## Что проверить перед показом

1. Заполнить `.env.local` личным API-токеном, не добавляя файл в Git.
2. Выполнить `npm install`, затем `npm run dev`.
3. Проверить загрузку профиля и карточек, редактирование профиля и аватара, создание карточки.
4. Проверить лайк, снятие лайка, отображение количества и удаление своей карточки с подтверждением.
5. Нажать на логотип и проверить четыре показателя статистики и три популярные карточки.
6. Выполнить `npm run build`, настроить secrets GitHub Actions и проверить публикацию в отдельный публичный репозиторий.
