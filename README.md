# Mesto — работа с сервером

Учебный проект спринта 10: приложение Mesto получает карточки и профиль из API, позволяет редактировать данные пользователя, создавать карточки, ставить и снимать лайки, удалять свои карточки и показывает статистику карточек по варианту 3.

## Запуск

Нужен Node.js 22.12 или новее.

1. Открой терминал в папке проекта и установи зависимости:

   ```sh
   npm install
   ```

2. В файле `.env.local` уже записан идентификатор группы `apf-cohort-203`. Вставь свой личный токен в строку `VITE_MESTO_TOKEN=`. Не добавляй заполненный `.env.local` в Git.
3. Запусти приложение:

   ```sh
   npm run dev
   ```

Если токен пустой, приложение откроется в режиме предпросмотра с демонстрационными карточками. Формы и лайки будут обращаться к API только после заполнения токена и перезапуска Vite.

## Реализованные пункты

- Получение профиля и карточек через `Promise.all` при запуске.
- Обновление имени и описания профиля (`PATCH /users/me`).
- Обновление аватара (`PATCH /users/me/avatar`).
- Создание карточки (`POST /cards`).
- Удаление карточки владельцем (`DELETE /cards/:id`) с окном подтверждения.
- Постановка и снятие лайка (`PUT`/`DELETE /cards/likes/:id`) и актуальный счётчик лайков.
- Индикаторы отправки форм: «Сохранение…», «Создание…», «Удаление…».
- Окно подробностей карточки, кнопка просмотра фотографии и адаптивная вёрстка по макету.
- Выбранный вариант 3: клик по логотипу открывает статистику карточек — число владельцев карточек, общее число лайков, максимальное число лайков от одного человека, чемпион по лайкам и три популярные карточки.
- Сборка Vite использует относительный `base: './'` для публикации в GitHub Pages.
- Workflow для автоматической сборки и публикации папки `dist` в отдельный публичный репозиторий.

Подробное соответствие заданию описано в [`CHECKLIST.md`](./CHECKLIST.md), а объяснение для защиты — в [`DEFENSE_GUIDE.md`](./DEFENSE_GUIDE.md).

## Публикация на GitHub Pages

Проект рассчитан на приватный репозиторий с исходниками и отдельный публичный репозиторий, содержащий только сборку из `dist`.

В настройках Actions приватного репозитория создай secrets:

| Secret | Значение |
| --- | --- |
| `PUBLIC_PAGES_TOKEN` | GitHub Personal Access Token с доступом `repo` к целевому публичному репозиторию |
| `PUBLIC_PAGES_REPO` | `владелец/название-публичного-репозитория` |
| `VITE_MESTO_GROUP_ID` | `apf-cohort-203` |
| `VITE_MESTO_TOKEN` | Личный токен API Практикума |
| `PUBLIC_PAGES_BRANCH` | Необязательно; по умолчанию `main` |

Создай целевой публичный репозиторий пустым. После первого успешного workflow в его настройках GitHub Pages выбери ветку публикации (обычно `main`) и каталог `/ (root)`. После этого каждый push в ветку `main` исходного репозитория пересобирает приложение и обновляет Pages.

> Примечание для защиты: Vite подставляет переменные `VITE_*` в клиентскую сборку. Поэтому API-токен будет доступен браузеру посетителя опубликованного приложения. Так устроен учебный клиентский API Практикума; не используй этот токен для других сервисов и не коммить `.env.local`.
